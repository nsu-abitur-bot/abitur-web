# Параллельный браузерный прогон

Исходный CI: [run 43006730805](https://github.com/nsu-abitur-bot/abitur-web/actions/runs/43006730805), 186 тестов, 8,4 минуты для Playwright. Тот PR менял версии actions, но не состав тестов. Более новый #76 содержит ещё четыре теста моделей: 190 тестов, 8,5 минуты — это отдельная выборка.

Основной расход — последовательное выполнение, а не production build. Для CI разрешены два worker. Четыре файла, меняющие общие profile/branding fake API и серверный кеш, выделены в chromium-stateful: один worker, запуск после chromium, chromium-sidebar и webkit. Общий сервер остаётся один; мутирующие сценарии не пересекаются с чтением остальных.

Состав сохраняется: 186 тестов в 22 файлах, тот же Chromium/WebKit, проверки ошибок/пустых состояний/мобильной версии, production artifact и отчёты. Сравнение длительности после изменения фиксируется по полному CI; ускорение не заявляется до результата.

При добавлении обращений к `/__test/branding` или `/__test/profile` в новые spec-файлы их нужно включить в sharedStateFiles. Ограничение не относится к context.route: его данные изолированы браузерным контекстом.
